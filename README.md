# AyayaJp

一个本地运行的日语 flashcard 程序，包含假名互记、N5/N4/N3 词汇与表达双向记忆、N5/N4/N3 语法练习；每个小板块都分成「认识」「模糊」「不认识」三部分，可一键切换。点击卡片翻面时会自动播放读音，答案区也可以手动重播；例句语音按与 furigana、罗马音相同的审核读音朗读（汉字转成假名，助词「は・へ」读作 wa・e），不让浏览器自己猜汉字读音，词缀卡朗读时去掉「～」；有多个标准读音的词会在读音栏一并列出（如「なん（也读 なに）」）。读音是用 [VOICEVOX](https://voicevox.hiroshiba.jp/)（VOICEVOX:No.7）预先生成的音频，通过 `<audio>` 播放，并把 audio session 设为 `ambient`，所以 iPhone 上的读音会和背景音乐混在一起播放，不会暂停音乐；静音模式和锁屏时读音也会静音（iPhone / iPad 的模块页会提示这一点）。没有对应音频的文本才退回浏览器 `speechSynthesis`，而 iOS 的 speechSynthesis 不受网页 audio session 控制，总会打断音乐（[WebKit bug 278598](https://bugs.webkit.org/show_bug.cgi?id=278598)）。
界面目前固定使用深色模式，没有浅色 / 深色切换按钮。
手机学习界面会铺满当前可用 viewport，并锁定页面本身的纵向滚动；只有模块页和高度很小的横屏卡片允许内部 touch scrolling。iOS 重播会避开 WebKit 中紧邻 `cancel()` / `speak()` 的竞争，在临时合成失败时自动重试一次，并显示明确的播放状态或错误提示。

在线网址：[https://ayaya114514.github.io/AyayaJp/](https://ayaya114514.github.io/AyayaJp/)

## 使用

直接打开 `index.html`，或在目录里启动一个本地 server：

```bash
python3 -m http.server 5173
```

然后访问 `http://localhost:5173`。

可以使用 `Tab` 在操作项之间移动；聚焦卡片后按 `Enter` 或 `Space` 显示答案。显示答案后按 `1` / `2` / `3` 分别评为 `认识` / `模糊` / `不认识`；选择题作答前按 `1`–`4` 选择 A–D。正常加载不会闪现状态提示；资源加载失败时会给出可见提示。

首屏只加载 `kana-cards.js` 和 `app.js`（约 45 KB gzip），假名模块立即可用；词库、语法、读音表、音频索引和 `card-data.js`（约 950 KB gzip）列在 `index.html` 的 `<template id="studyDataScripts">` 里，由 `app.js` 在第一张卡显示后按顺序加载。上次停在词汇 / 语法卡组的访问者，`index.html` 会凭 `ayaya-jp-start-family-v1` 这个小标记立即 preload 这些文件，与首屏并行下载。数据未到时，需要它的卡组显示「正在加载…」（加载很快时不出现），并且不会改写已保存的这一轮进度；超过 0.8 秒仍未就绪时页面顶部也会出现加载提示，在此之前的按钮先变暗、不可点。词汇卡的例句（furigana、罗马音、朗读文本）在卡片第一次显示时才计算；隐藏的标签页只记下其他标签页的写入，切回时再合并。

## 检查

Validation 需要 Node.js 20 或更新版本；推荐使用 `.nvmrc` 指定的 Node 22：

```bash
nvm use
npm run check
```

`npm run check` 会依次运行 source/runtime/DOM validation、bundle baseline validation 和 app contract tests。它会检查 JS 语法、HTML 结构与本地资源、脚本依赖顺序、N5/N4/N3 JS/JSON 数据一致性、词库和语法字段完整性、助词与词内音节的 romaji regression cases、lazy card builders、stable/legacy/retired source IDs，以及 app 的 storage、TTS、sidebar 等关键 contracts。

完整测试还会运行真实 Chromium 与 WebKit，在 desktop、320×640 mobile viewport、iPhone 14 的 390×664 可用 viewport 和横屏 viewport 检查卡片布局、整面点击、focus、Back/Undo、多标签页进度合并与刷新行为：

```bash
npm test
```

浏览器测试固定使用专用端口 4318 启动静态 server，并且不复用已在运行的 server，避免误测其他项目（例如同样默认 4173 的 Vite preview）。首次在本机运行前，或升级 `@playwright/test` 后浏览器 build 号变化时，需要安装 Chromium / WebKit：

```bash
npx playwright install chromium webkit
```

GitHub Pages 只会在 contracts 和 browser regressions 全部通过后部署。部署 artifact 会为每个 CSS/JS 加入基于该文件内容 hash 的版本参数：改过的文件换新 URL，避免 CDN cache 混用新旧资源；没改的文件保持原 URL，回访时不必重新下载几 MB 的词库数据。

部署 artifact 里的词库、语法和读音表（`n5/n4/n3` 词汇、`grammar-data.js`、`pitch-accent-data.js`、`romaji-word-spacing.js`、`example-readings.js`）会把开头的数据 literal 改写成 `JSON.parse('<minified JSON>')`，体积更小、解析更快；源文件保持原样。`build:pages` 会核对改写前后定义的全部 `window` 数据完全相同，否则构建失败。`npm run test:site` 先构建再对 `_site/` 跑同一套浏览器测试。

`sw.js`（service worker，只在 https 和 localhost 注册）让学过的内容可以离线打开、回访不必逐个重新验证资源：页面 network first（内容修正能立即生效，离线或 3 秒无响应时用缓存）；带 `?v=` 的 CSS/JS 按内容 hash cache first；读音音频先用缓存、后台更新（原地重新生成的音频下一次播放时生效）。要整体清空缓存时改 `sw.js` 的 `CACHE_VERSION`。

`validation-report.json` 是 committed baseline manifest，只记录受检 source fingerprint、预期计数和必须执行的 contracts；它不是“检查已经通过”的结果报告。只有在有意修改受检 source 或计数后才更新它：

```bash
npm run update:manifest
npm run check
```

Updater 是 deterministic 的，并会在 N5/N4/N3 JS/JSON 未同步时拒绝改写 manifest。

## 练习逻辑

- 学习界面从上到下排列：顶部是浅色的单词区（左上角的 `<` 撤回上一次评分，题目和读音带播放按钮；语法 `日→中` 卡以文型为大字题面，句子作为下方小字；`中→日` 卡正面只显示中文句子和所属分组，文型翻开后才出现，免得题面直接给出答案），下方深色的答案区在翻开前提示「点击屏幕显示答案」，翻开后依次是意思、「说明」（读音、接续、提示等逐行列出）和「例句」，`认识` / `模糊` / `不认识` 固定在下方。宽度够两栏（iPad 横屏、桌面）时卡片加宽，「说明」和「例句」左右并排。翻开后的全部内容在 390×844 手机竖屏、1280×800 桌面窗口和 11 寸 iPad Air 的 Safari（竖屏 820×1100、带标签栏的横屏 1180×700）内一屏放下、不需要滚动；Playwright 会逐张检查全部卡片，提示文字过长导致超出时测试失败。最底部的浅色导航栏从左到右是 `当前`、`模糊`、`不认识`（角标分别为该板块本轮剩余张数）和 `模块`（打开模块页，再点一次或点 `<`、`当前`、`模糊`、`不认识` 回到学习）。
- 模块页先是「基础」一行，再按级别分成 N5 / N4 / N3 三组，每组是「词汇」「语法」两行；格子是练习方式；语法行按推荐的学习顺序排成 `文型` → `选择题` → `日→中` → `中→日`（先认识文型的意思和接续，再在句子里填空，最后做整句的理解和产出）；每组的标题、分隔线和格子边框带该级别的颜色，组与组之间留出比行间更大的间距。宽屏时内容最宽 860px，手机竖屏一屏放下全部模块，点一下即可切换；完成的轮数显示在格子右上角，0 轮不显示。
- 所有普通模块按随机顺序出题，一轮练完后可以点 `重新开始` 再洗牌。
- `认识`、`模糊`、`不认识` 只记录你的选择，不计算复习间隔。
- 日→中词汇卡正面只显示词形；写法完全相同、读音和意思不同的词（十 じゅう／とお、一日 いちにち／ついたち、私 わたし／わたくし 等，包括分在 N5 / N4 两级的 空 そら／から、開く あく／ひらく，N4 / N3 的 表 おもて／ひょう，以及 N3 内的 注ぐ そそぐ／つぐ、額 がく／ひたい）会在正面显示读音，否则无法判断问的是哪一张。
- 每个小板块（假名、词汇各方向、语法各题型）都有自己的「模糊」和「不认识」板块，点底部导航栏的 `模糊` / `不认识` 切换过去，点 `当前` 回来。
- 选 `模糊` / `不认识`（或选择题答错）会立即把卡片移进该板块的「模糊」/「不认识」部分并从原板块去掉；在「模糊」或「不认识」里选 `认识`（或答对）会移回主板块，并算作主板块本轮已完成；两者之间也可以互相移动。一轮做完后，主板块只剩认识的，「模糊」「不认识」里分别只剩模糊和不认识的。选择题答错进「不认识」；打开「提示」后才答对的进「模糊」，不算认识。
- 旧版本评为 `不确定` 的卡片归入「模糊」板块，评为 `遗忘` 或答错的归入「不认识」板块。
- 语法模块按 N5/N4/N3 分开练 `文型`、`选择题`、`日→中` 和 `中→日`。每级语法按功能分组（N5 17 组、N4 23 组、N3 24 组），容易混的放在同一组：如 N4「条件」组是 ば／たら／と／なら／場合は，「样子与比喻」组是 そうだ／ようだ／みたいだ／らしい 等。
- 词汇和语法都分成「小块」：模块页点词汇或语法的格子后，先进这个模块的小块页（`<` 回到模块页），最上面是「全部」，下面是各个小块。每个格子显示块号和本轮还剩几张（练完显示「✓ 完成」），右上角是完成轮数；格子背景从左往右按比例着色：绿色是本轮已认识的，黄色是模糊的，红色是不认识的。边框颜色取最需要处理的那一种：有不认识就是红框，只有模糊是黄框，整块练完是绿框。正在练的那一块外面多一圈蓝色光环。点一下就开始练这一块。练词汇或语法时点底部的 `模块` 会直接回到这个模块的小块页（并聚焦正在练的那一块），再点 `<` 才是整个模块页；练假名时 `模块` 打开的仍是模块页。
  - 词汇每级随机分块，每块 25–26 张（N5 29 块、N4 29 块、N3 61 块）。分块按词条 ID 的固定 hash 顺序切开，所以每次打开都一样；以后新加的词（`app.js` 的 `VOCAB_BLOCK_GENERATIONS` 里记着每级已发布的最大编号）单独组成排在后面的新块，不会打乱已经在练的块；日→中 和 中→日 用同一套分块，同一块里是同一批词。语法的小块就是上面的功能分组。
  - 每个小块都是独立的板块：有自己的 `当前` / `模糊` / `不认识` 和轮数，块内照常随机出题。练完后「重练这一块」只在块内重新洗牌，不影响其他块和「全部」；「下一块」直接进入下一块。日→中 和 中→日 各自记住自己练到哪一块。
  - 第一次打开某个小块时，它沿用「全部」这一轮里属于这一块的进度（已经练过的不再重出）。评分记在卡片上，所以在小块里选的 `模糊` / `不认识` 在「全部」的同名板块里也看得到。
  - 旧版本在模块页下拉框里选过的语法分组，升级后会直接进入对应的小块。
- 语法卡片翻开前的标签是所属分组；`文型` 卡和选择题翻开后的「说明」有一行「辨析」，一句话说明它和最容易混的语法有什么不同（`日→中` / `中→日` 卡的例句较长，为了一屏放下不显示这一行）。
- 语法选择题是填空题：这条语法的每句例句各出一题（每条语法 3 题），从例句里挖掉文型部分，题面是日语句子和中文译文，四个选项是正确形式和三个逐条审核过的错误选项（同组容易混的语法、错误的接续或变形、意思不对的说法），每个错误选项都附上为什么不对。中文译文固定了句意，同样正确的说法（如 ば／たら 都通的句子）不会同时出现在选项里，保证只有一个正确项。每轮重新开始会重新打乱题目顺序，每题选项顺序也会重新打乱，并避免正确项连续落在同一位置。还没掌握的语法可以在作答前点选项上方的「提示」（键盘 `H`），列出这条语法的文型和接续；看了提示再答对的题进「模糊」。
- 语法选择题答题后（手机和桌面都一样）只保留你的选择与正确项的解释，下面是「辨析」和补全后的例句（带 furigana、罗马音和读音）；「回答正确／回答错误」只读给屏幕阅读器，选项颜色和「你的选择／正确项」标签已经表明对错。
- `文型` 卡正面只显示文型和所属分组（例句会直接泄露意思，所以不放在正面），翻开后答案只显示意思，接续和提示放在「说明」里逐行列出。
- 所有语法卡的「例句」里，句子中属于这条语法的部分（如 `〜てはいけません`、`より〜のほうが` 的两段）用金色标出；高亮范围逐句写在例句的 `focus` 里，部分覆盖一个带读音的词时整词标出，读音不被拆开。
- 选择题会保留最近一次选择结果，以便刷新或多标签页同步后继续显示正确解释。

所有进度保存在浏览器 `localStorage` 中。存储使用 bounded schema：每张卡只保留累计次数、最近评分和单个同步事件，不保存随练习次数增长的记忆链条或 Undo tombstone history；“完成轮数”只是一个数字，不会按轮追加记录。Undo 只在这张卡上记下最近一次撤销的评分事件（`undoneEventId`，一个字段），已经合并过这次评分的其他标签页据此把它撤掉，而不会当成被覆盖的进度写回去；撤销的是这张卡的第一次评分时，卡片保留一条 0 次的记录来带上这个字段。

每次评分都会把整个进度写回 `localStorage`。存储里仍是这个标签页上次同步的内容时（没有其他标签页写入），合并直接采用本页的卡片状态，不再逐张比较；全部约 8,000 张卡都评过、所有小块都打开过的极端情况下，4 倍 CPU 降速时每次评分约 120 ms（修改前约 180 ms）。

Safari 会清除一段时间没有访问的网站的 localStorage（WebKit 的 7 天脚本存储上限；添加到主屏幕的 web app 不受影响）。开始评分后页面会请求 `navigator.storage.persist()`。页面带 web app manifest 和 apple-touch-icon，可以添加到主屏幕使用。

## 词库数据来源

当前项目完全使用 `n5-codex-vocab.js` / `n5-codex-vocab.json` 作为 N5 数据源，共 743 条（含 2026-10-23 为同音词补入的 18 条，见下文「同音词」）。
当前项目完全使用 `ayaya-n4-codex-vocab.js` / `ayaya-n4-codex-vocab.json` 作为 N4 数据源，共 745 条（含为同音词补入的 18 条）。
当前项目完全使用 `ayaya-n3-codex-vocab.js` / `ayaya-n3-codex-vocab.json` 作为 N3 数据源，共 1,526 条（含为同音词补入的 39 条）。

数据字段包括规范词形、原始词形、变体、读音、罗马音、词性、简体中文释义、整词 furigana 信息、教学分类，以及每项 3 条日语例句和简体中文翻译。卡片会明确标出词汇、量词、词缀、表达、复合词、派生形式、固定表达或搭配，不再把它们统一显示成“单词”。

前端实际加载 `n5-codex-vocab.js`、`ayaya-n4-codex-vocab.js` 和 `ayaya-n3-codex-vocab.js`。对应 `.json` 文件保留为同源的可读/可校对数据文件。

### 读音音频（VOICEVOX）

- `npm run build:audio` 调用本机 VOICEVOX engine（默认 `http://127.0.0.1:50021`，可用 `VOICEVOX_URL` 指定；engine 从 [voicevox_engine releases](https://github.com/VOICEVOX/voicevox_engine/releases) 下载），为 app 会朗读的每条文本（假名卡、词汇读音、全部例句）生成 `audio/no7-announce-v4/<key>.mp3`，并写出 `audio-manifest.js` 和 `audio/report.tsv`。文件名是文本的 hash，只渲染还没有音频（或音调标注改过）的文本；`--prune` 删除不再使用的音频。改声音或合成参数时要换一个新目录名，避免浏览器缓存混用新旧音频。
- 响度：为了边听音乐边学时也能听清，每条音频先削掉低频和 250 Hz 闷音、提升 3 kHz / 6 kHz 的清晰度，再压缩，然后把有声部分统一到约 -11.5 LUFS（句子），经 limiter 后以 48 kbps 编码；编码后解码峰值超过 -0.5 dBFS 的会自动降一点重新编码，避免播放时削波。
- 读音 fail closed：engine 最终要念的每一拍（mora）必须和审核过的读音（与 furigana / 罗马音同源的 `speech`）完全一致，只把 ー / えい / おう 这类同音写法视为相同；对不上就不生成音频，该文本继续使用 speechSynthesis。例句优先用汉字原文合成（音调更自然），engine 读错的汉字换成审核读音的片假名后重试。「どういう／そういう／こういう」的「いう」按标准发音读作「ゆう」，这是脚本里逐条列出的审核例外。
- 音调：有 Kanjium 音调的词汇按第一个音调合成；进阶发音的例词按脚本里逐条核对过 Kanjium 的音调表合成；其余文本先用 VOICEVOX 的判断。全部例句和无 Kanjium 音调的词汇都逐条人工审核过：VOICEVOX 判断错的（一段动词て形、ない形、く形、名词音调、复合词和「の」的切分、疑问句升调等）在 `audio-prosody.tsv` 里逐条写出东京音的音调短语（`/` 分短语，`'` 标在调核之后，`？` 为疑问升调，`、` 为停顿），生成时按它重组 engine 自己的音拍；音拍对不上就不生成，validation 失败。`audio/report.tsv` 列出每条文本的生成方式和实际音调（用了审核音调的标 `+prosody`），供审核。
- 同音词：音频按文本 hash 命名，读音相同但单独念时音调不同的词（雨 ア'メ／飴 アメ、橋 ハシ／箸 ハ'シ、暑い／厚い、帰る／変える、切る／着る 等，以及没有 Kanjium 音调、只能靠 engine 判断的同音词）各自使用「假名｜词形」的音频文本（如 `あめ｜飴`），按自己的音调合成，不再共用一个音频；单念时听起来一样的（花 ② ／鼻 ⓪ 这类尾高与平板）和词缀卡（～回、～本）仍共用。规则在 `card-data.js` 的 `homophoneClipTexts()`，contract test 会检查。
- engine 预测的音高并不总是符合它自己的音调标注：经常把峰值放在调核后一拍（`雨 ア'メ` 会念成 ア < メ，听起来像 `飴`），词尾也常掉下去（`足 アシ'` 会念成 ア > シ，像头高型）。生成脚本按每个音调短语的标注重塑音高：第二拍是普通音拍时第一拍低约 3.5 个半音，高的部分连续不塌，调核是到下降处为止的最高点，其后各拍至少低约 5 个半音；调核上被清化的元音（`デ'ス` 的 ス 等）改为浊化。
- validation 要求每条朗读文本都在 `audio/report.tsv` 里有对应当前文本的记录，`audio-prosody.tsv` 的每一条都对应一条朗读文本并且已按它生成，manifest 里的音频文件都存在，并且页面上显示 `音声：VOICEVOX:No.7` 署名。修改例句或读音后要重新运行 `npm run build:audio`，并审核新文本在 `audio/report.tsv` 里的音调，错的写进 `audio-prosody.tsv`。
- 声音使用条款：VOICEVOX 及 No.7 允许署名后非商用免费使用（[No.7 利用規約](https://voiceseven.com/)）。
- 音频随仓库一起提交，GitHub Pages 直接发布。每次换目录全量重新生成都会给 git 历史永久增加约 80 MB，所以只在声音或合成参数确实需要改变时才换目录；修改例句时 `npm run build:audio` 只生成缺少的音频。

### 音调（pitch accent）

- 翻面后读音后面会标东京音调核位置，例如 `读音：あめ ①`、`读音：ともだち ⓪`；有多个公认音调时写成 `④/⓪`。
- 数据来自 [Kanjium](https://github.com/mifunetoshiro/kanjium) 的 `accents.txt`（"The pitch accent notation ... were provided by Uros O. through his free database"），按 [CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/) 使用；`pitch-accent-data.js` 是它的派生数据，以相同许可分发。
- 只在 Kanjium 精确收录「词形 + 读音」且只有纯数字音调时标注（纯假名词仅在唯一的汉字变体匹配时补上）；带词性分义的条目（如 `結構`、`大事`）、后缀和句型、以及人工审查认为义项不对应的条目（`ああ`、`ええ`、`ちゃん`、`君（くん）`），以及公认有 ①/③ 两种音调而 Kanjium 只收 ③ 的 `講義`，不标注。`これ` / `それ` 使用 Kanjium 中指示代词义项（此れ / 其れ）的数据。当前 3,014 条词汇中 2,705 条有音调（N3 的感叹词 `おや` Kanjium 未区分义项，不标注）。
- 重新生成：`npm run build:pitch -- <path/to/kanjium/accents.txt>`；人工审查的排除和改指向写在 `scripts/build-pitch-accents.js` 里，validation 会检查索引范围、来源许可和这些审查结果。

### 同音词

- 读音相同的词（紙・髪・神、橋・端・箸、雨・飴）翻开后在「说明」里多一行「同音」，按常用程度编号，每个词后面是它自己的音调和释义，当前这张卡的词用金色标出，例如 `同音 1 神 ① 神　2 髪 ② 头发　3 紙 ② 纸`。同一组的卡出题时不会紧挨着出现（洗牌后有相邻的就和别处的卡交换）。
- 分组和顺序写在 `homophone-data.js`。顺序按国立国语研究所 [BCCWJ 词频表](https://clrd.ninjal.ac.jp/bccwj/freq-list.html)（短单位、每百万词频次；研究和教育用途可免费使用，这里只用来排序）；UniDic 把几种写法算成同一个词的（帰る・返る、降りる・下りる、早い・速い、勤める・務める 等），参考 JMdict 的报纸词频档位和各义项的常用程度人工排定。每个释义都是该词现有中文释义里的一段，不另写新译文；音调来自上面的 Kanjium 数据，没有可靠音调的不显示。同一个词按义项拆成两张卡的（两张「うち」「そう」「向こう」）不算同音词。
- validation 要求词库里每一组读音相同的词（词缀除外）都写进 `homophone-data.js`，而且只出现一次，释义必须来自该词的 `meaning_zh`。
- 2026-10-23 为同音词补入 75 个词条（新词并入同组里最低的级别），都是 BCCWJ 每百万词 20 次以上、单独使用的常用词（例外：「写る」15 次，因为与「移る」「映る」是日常最需要区分的一组而保留）：
  - N5（18）：思い、返る、核、かく（掻く）、過程、区、個々、策、死、汁、つく（点く）、努める、務める、番、拭く、防止、優しい、液。
  - N4（18）：意図、窺う、映る、写る、海上、かつ（且つ）、協会、公害、向上、自己、自信、時点、児童、天、煮る、幼児、分かれる、枠。
  - N3（39）：依然、衛生、負う、官僚、期限、機構、協議、曲、菌、血管、件、剣、減少、公正、自体、視点、脂肪、生涯、進行、申告、酢、全身、像、捜査、創造、対照、次ぐ、問う、説く、得、覗く、図る、票、部隊、兵、経る、補償、巻く、容器。
  - 新词的编号接在每级历史上用过的最大编号之后（N4 从 `n4-768` 开始，`n4-760`–`n4-767` 是已退役、迁到语法卡的旧词）。单字词「曲（きょく）」的读音只用于自己的例句（`entryScopedReadingIds`），否则会把「曲がる」标错。前缀/后缀/量词类（機、旧、各、〜語、週間、巻、台、代）、专有名词（藩、厚生）、语法形式（因る；〜せいで、〜て以来、たとえ〜ても、〜たびに、〜とともに、〜をもとに 已是语法卡；〜ふりをする、〜ほうがいい 一类不做词汇卡）、主要出现在复合词里的（自転、助成、療法）、同一个词的不同写法和外来语没有收；「描く（かく）」已作为 N3「描く」的又读收录，不重复出卡。新例句逐句核对了语义、自然度、译文、furigana、罗马音分词和读音；音调与 OJAD「スズキクン」的预测逐句对照，修正了 VOICEVOX 在一段动词て形（かけて、漏れて、努めて）、促音上的调核（返って）、「〜方」「大きく」「話して」「書かれて」「いい」「だれでも」「寝て」上的错误，以及一个疑问升调。

## 语法数据

当前项目使用 `grammar-data.js` 作为 N5/N4/N3 语法数据源，共 333 条（N5 85 条、N4 130 条、N3 118 条），分成 64 个组（`groups`）。每条语法包含所属分组、文型、中文意思、接续、提示、辨析、中文 prompt、标准日语答案、3 条例句（每句带高亮范围 `focus`），以及每句例句各一道填空题（`drills`：用哪句例句、挖掉的部分、三个错误选项及原因；`drills[0]` 沿用以前唯一那道题的卡片 ID，保留进度）。退役的语法条目记在 `retiredEntries`（指向接手的词汇条目），它们的 ID 不再使用；并入另一级别同一语法的条目记在接手条目的 `retiredGrammarIds`，旧条目每张卡（`中→日`、`日→中`、`文型`、每道选择题）的进度迁移到接手条目的同类卡；validation 会检查每句例句正好有一道题、每个挖空在例句里只出现一次、选项互不相同、每个错误选项都有原因，以及每句的 `focus` 都按顺序出现在句子里。

`card-data.js` 会为每条语法生成 6 张卡：`中→日`、`日→中`、`文型` 各一张，`选择题` 每句例句一张。当前完整数据包计数为：

- 假名 / 发音卡片：241
- 词汇与表达卡片：6,028
- 语法卡片：1,998
- 总卡片：8,267

“进阶发音”分为浊音、半浊音、拗音、长音、促音、拨音、助词和外来音，每张卡只用一个词标注类别，翻面后用「类别：假名　罗马音：…　例词：…」的简短格式说明；`コーヒー` 等整词只作为发音例词，不再与 N5 词义卡重复出题。该模块是教学精选，不表示使用频率，也不是完整外来音表。

## 文件结构

- `index.html`：页面结构和脚本加载顺序。
- `styles.css`：页面样式。
- `kana-cards.js`：假名与进阶发音卡（首屏加载）。
- `card-data.js`：N5/N4/N3 数据转换、例句和卡片构建逻辑（随学习数据后加载）。
- `grammar-data.js`：N5/N4/N3 语法练习数据。
- `pitch-accent-data.js`：由 `scripts/build-pitch-accents.js` 从 Kanjium 生成的词汇音调数据（CC BY-SA 4.0）。
- `homophone-data.js`：同音词分组，按词频排序，每个词带一段审核过的释义（见「同音词」）。
- `app.js`：学习状态、渲染、交互和语音播放逻辑。
- `sw.js`：离线缓存与回访加速的 service worker（见“检查”一节）。
- `audio-manifest.js` / `audio/`：由 `scripts/build-audio.js` 生成的 VOICEVOX 读音音频索引、音频文件和生成报告。
- `scripts/validate.js`：本地 zero-dependency source/runtime/DOM validation。
- `scripts/test-app-contracts.js`：zero-dependency app regression tests。
- `scripts/update-validation-manifest.js`：deterministic baseline manifest updater。
- `scripts/sync-vocab-js.js`：由 N5/N4/N3 JSON 生成对应的 JS 数据文件（`npm run sync:vocab`，`--check` 只检查不写入）。
- `validate-bundle.js` / `validation-report.json`：bundle baseline checker 与 committed manifest（不是通过结果报告）。
